## 三、分类模块实现（较简单，练手）

分类模块结构简单，与阶段二的商品 CRUD 几乎一样，这里给出核心代码：

```java
@Data
@TableName("category")
public class Category {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String name;
    private Integer sort;
    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;
    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

```java
@Service
public class CategoryService extends ServiceImpl<CategoryMapper, Category> {

    private final ProductMapper productMapper;      // 删除前要查 product 表，需注入 ProductMapper

    public CategoryService(ProductMapper productMapper) {
        this.productMapper = productMapper;
    }

    // 删除前校验：分类下有商品则不允许删除
    public void deleteCategory(Long id) {
        long count = productMapper.selectCount(
                new QueryWrapper<Product>().eq("category_id", id));
        if (count > 0) {
            throw new BusinessException("该分类下存在商品，无法删除");
        }
        this.removeById(id);
    }
}
```

> ⚠️ 注意：`productMapper` 不是自动就有的，必须像上面这样**声明字段并构造器注入 `ProductMapper`**（并补 `import com.mall.mall.mapper.ProductMapper;`）。跨表查询时给 Service 注入另一个 Mapper 是常见做法——忘了注入直接使用会报「无法解析符号」。Category 实体、CategoryMapper 与阶段二商品 CRUD 相同，不再重复贴。

> 注意点：**删除分类前要检查关联数据**，这是后端「数据一致性」意识的体现。阶段六下单会反复遇到。

## 四、商品模块实现

> ⚠️ **动手前必须先做一步：升级 `Product` 实体。**
> 阶段二的 `Product` 是简版（只有 `id` / `name` / `price` / `stock`），而阶段三建表时 `product` 表已经是**正式版**（多了 `merchant_id`、`category_id`、`description`、`status`、`main_image`）。
> 如果跳过这一步，下面 Service 里的 `product.setStatus(1)` 会直接报「找不到符号」，`BeanUtils.copyProperties(dto, product)` 也会因为字段对不上而**一个字段都拷不过去**，插库时被 `NOT NULL` 拦下。

### 1. 实体类（Entity）升级

```java
package com.mall.mall.entity;

import com.baomidou.mybatisplus.annotation.*;
import lombok.Data;

import java.math.BigDecimal;
import java.time.LocalDateTime;

@Data
@TableName("product")
public class Product {

    @TableId(type = IdType.AUTO)
    private Long id;

    private Long merchantId;            // 所属店家（驼峰自动映射 merchant_id）
    private Long categoryId;            // 所属分类（驼峰自动映射 category_id）
    private String name;
    private String description;
    private BigDecimal price;           // ⚠️ 从 Double 改成 BigDecimal
    private Integer stock;
    private Integer status;             // 1上架 0下架
    private String mainImage;           // 主图 URL

    @TableField(fill = FieldFill.INSERT)
    private LocalDateTime createTime;

    @TableField(fill = FieldFill.INSERT_UPDATE)
    private LocalDateTime updateTime;
}
```

> 两个关键点，漏一个都会卡住：
> 1. **`price` 必须从 `Double` 改成 `BigDecimal`**。数据库列是 `DECIMAL(10,2)`；更要命的是 `BeanUtils.copyProperties` **只在类型兼容时才拷贝**，`BigDecimal → Double` 会被静默跳过，价格永远是 `null`。金额一律 `BigDecimal` 是后端铁律（详细原因见 [阶段二](./03-阶段二-数据库设计与持久层.md)）。
> 2. **驼峰字段名会自动映射下划线列名**：`merchantId` ↔ `merchant_id`，MyBatis-Plus 默认开启驼峰转换，不需要手写 `@TableField`。
>
> **同时确认数据库结构**：如果你的 `product` 表还是阶段二 `01-schema.sql` 建的简版，先在客户端执行 `DESC product;` 看有没有 `merchant_id` 字段——没有就按 `sql/03-阶段三-商城建表.sql` 开头的注释重建（`DROP TABLE IF EXISTS product;` 后重跑该文件）。**表结构不对，代码再对也会报 `Unknown column`。**

> 三个类都放在各自的包里：`dto/ProductCreateDTO.java`、`dto/ProductQueryDTO.java`、`vo/ProductVO.java`（`vo` 包阶段四写 `MerchantVO` 时已经建好，直接放进去即可）。
>
> **VO 比实体只多了 `categoryName` 一个字段**，这正是 VO 存在的意义：实体对应数据库表，VO 对应前端要展示的内容。数据库里商品只存 `category_id`，前端列表却要显示「手机数码」这样的分类名——这个"名字"不属于商品表，所以要单独查出来塞进 VO。

### 3. Service（核心逻辑）

```java
@Service
public class ProductService extends ServiceImpl<ProductMapper, Product> {

    private final MerchantService merchantService;
    private final CategoryService categoryService;

    public ProductService(MerchantService merchantService, CategoryService categoryService) {
        this.merchantService = merchantService;
        this.categoryService = categoryService;
    }

    // 新增商品：校验店家与分类存在
    public void createProduct(ProductCreateDTO dto) {
        if (merchantService.getById(dto.getMerchantId()) == null) {
            throw new BusinessException("店家不存在");
        }
        if (categoryService.getById(dto.getCategoryId()) == null) {
            throw new BusinessException("分类不存在");
        }
        Product product = new Product();
        BeanUtils.copyProperties(dto, product);
        product.setStatus(1);   // 默认上架
        this.save(product);
    }

    // 查询商品详情（查不到直接抛异常，交给全局处理器转成统一返回）
    public ProductVO getProduct(Long id) {
        Product product = this.getById(id);
        if (product == null) {
            throw new BusinessException("商品不存在");
        }
        return toVO(product);
    }

    // 修改商品：校验存在性后更新
    public void updateProduct(Long id, ProductCreateDTO dto) {
        if (this.getById(id) == null) {
            throw new BusinessException("商品不存在");
        }
        if (merchantService.getById(dto.getMerchantId()) == null) {
            throw new BusinessException("店家不存在");
        }
        if (categoryService.getById(dto.getCategoryId()) == null) {
            throw new BusinessException("分类不存在");
        }
        Product product = new Product();
        BeanUtils.copyProperties(dto, product);
        product.setId(id);      // 用路径参数指定的 id
        // status 为 null，updateById 默认只更新非 null 字段，所以上架状态不会被覆盖
        this.updateById(product);
    }

    // 分页 + 多条件查询
    public Page<ProductVO> page(ProductQueryDTO query) {
        QueryWrapper<Product> wrapper = new QueryWrapper<>();
        if (query.getMerchantId() != null) {
            wrapper.eq("merchant_id", query.getMerchantId());
        }
        if (query.getCategoryId() != null) {
            wrapper.eq("category_id", query.getCategoryId());
        }
        if (query.getStatus() != null) {
            wrapper.eq("status", query.getStatus());
        }
        if (query.getKeyword() != null && !query.getKeyword().isBlank()) {
            wrapper.like("name", query.getKeyword());
        }
        wrapper.orderByDesc("id");

        Page<Product> page = this.page(
                new Page<>(query.getPageNum(), query.getPageSize()), wrapper);

        // 转 VO，并填充分类名（展示用）
        Page<ProductVO> voPage = new Page<>(query.getPageNum(), query.getPageSize(), page.getTotal());
        voPage.setRecords(page.getRecords().stream().map(this::toVO).toList());
        return voPage;
    }

    // 上架/下架
    public void changeStatus(Long id, Integer status) {
        Product product = this.getById(id);
        if (product == null) {
            throw new BusinessException("商品不存在");
        }
        product.setStatus(status);
        this.updateById(product);
    }

    // 库存入库
    public void stockIn(Long id, Integer quantity) {
        if (quantity == null || quantity <= 0) {
            throw new BusinessException("入库数量必须大于0");
        }
        Product product = this.getById(id);
        if (product == null) {
            throw new BusinessException("商品不存在");
        }
        product.setStock(product.getStock() + quantity);
        this.updateById(product);
    }

    // 实体 -> VO 转换：补上 VO 里多出来的 categoryName
    public ProductVO toVO(Product p) {
        ProductVO vo = new ProductVO();
        BeanUtils.copyProperties(p, vo);
        Category c = categoryService.getById(p.getCategoryId());
        vo.setCategoryName(c != null ? c.getName() : null);
        return vo;
    }
}
```

### 4. Controller

```java
@RestController
@RequestMapping("/api/products")
public class ProductController {

    private final ProductService productService;

    public ProductController(ProductService productService) {
        this.productService = productService;
    }

    @PostMapping
    public Result<Void> create(@Valid @RequestBody ProductCreateDTO dto) {
        productService.createProduct(dto);
        return Result.success();
    }

    @GetMapping("/{id}")
    public Result<ProductVO> get(@PathVariable Long id) {
        // 走 Service 的 getProduct：查不到会抛 BusinessException，由全局处理器返回统一错误
        return Result.success(productService.getProduct(id));
    }

    @GetMapping("/page")
    public Result<Page<ProductVO>> page(ProductQueryDTO query) {
        return Result.success(productService.page(query));
    }

    @PutMapping("/{id}")
    public Result<Void> update(@PathVariable Long id, @Valid @RequestBody ProductCreateDTO dto) {
        productService.updateProduct(id, dto);
        return Result.success();
    }

    @DeleteMapping("/{id}")
    public Result<Void> delete(@PathVariable Long id) {
        productService.removeById(id);
        return Result.success();
    }

    @PutMapping("/{id}/status")
    public Result<Void> changeStatus(@PathVariable Long id, @RequestParam Integer status) {
        productService.changeStatus(id, status);
        return Result.success();
    }

    @PostMapping("/{id}/stock-in")
    public Result<Void> stockIn(@PathVariable Long id, @RequestParam Integer quantity) {
        productService.stockIn(id, quantity);
        return Result.success();
    }
}
```

> 项目里通常写一行通配导入更省事，这里逐条列出只是为了让每个类来自哪里更清楚。

两个容易踩的点：

- `@GetMapping("/page")` 和 `@GetMapping("/{id}")` **不会冲突**：Spring 优先匹配精确路径 `/page`，其余才落到 `/{id}`。
- `page(ProductQueryDTO query)` 没有 `@RequestBody`：查询参数（`?pageNum=1&pageSize=10`）由 Spring 按 setter 绑定到 DTO 字段，所以 `ProductQueryDTO` 必须有 `@Data` 提供 setter。


## 五、关键设计思考

1. **VO 里补充 `categoryName`**：数据库里商品只存了 `category_id`，但前端展示需要分类名。两种方案：
   - 查询后补查分类（如上），简单直接；
   - SQL 联表（`JOIN`）一次查出，性能更好。阶段八可以优化。
2. **库存变更要谨慎**：这里用「先查后改」的 `getById + updateById`，单机学习够用。但在高并发下会有「超卖」问题（多个请求同时读到库存 10，都扣成 9）。阶段六会引入「原子扣减」，阶段八会用乐观锁/悲观锁解决并发。
3. **所有写操作都要校验数据存在性**：新增商品要校验店家、分类存在，这是「数据一致性」的基本功。

## 七、常见坑

| 问题 | 原因与解决 |
| --- | --- |
| **`product.setStatus(1)` 报「找不到符号」** | `Product` 实体还停在阶段二简版，没有 `status` 字段。**实体必须跟着表结构一起升级**（见第四节开头），Lombok 只给已声明的字段生成 setter |
| **插入报 `Unknown column 'merchant_id'`** | 实体改对了但数据库表还是简版。先 `DESC product;` 确认，没有新字段就 `DROP TABLE IF EXISTS product;` 后重跑 `sql/03-阶段三-商城建表.sql` |
| **`copyProperties` 之后字段全是 null** | 源和目标**同名但类型不同**时会静默跳过（最典型：`BigDecimal price` → `Double price`）。金额两端统一用 `BigDecimal` |
| **接口返回 `[]` / 裸对象，前端拿不到 code** | `Result` 不会自动包装。方法**返回类型**要声明成 `Result<T>`，方法体里显式 `return Result.success(...)` |
| 金额精度丢失 | 价格/金额一律用 `BigDecimal`，别用 `Double` |
| 组合查询条件互相覆盖 | 用 `if` 判断逐个 `wrapper.xxx()` 拼接，不要无脑全拼 |
| 删分类后商品分类悬空 | 删除前校验关联商品数 |
| `@RequestParam` 缺参报 400 | 给默认值或 `required=false`，或改用 DTO 接收查询参数 |
| 请求路径报 `NoResourceFoundException` | 不是异常处理失效，而是**路径没匹配上任何 Controller**（单复数、拼写）。找不到映射时 Spring 会退回静态资源处理器，找不到文件就抛这个异常 |
