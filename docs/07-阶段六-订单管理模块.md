# 07 · 阶段六：订单管理模块

> 目标：完成商城最核心的交易模块——订单，掌握「下单事务」「库存扣减」「订单状态机」「订单查询」。
> 验收标准：下单能同时完成「生成订单 + 生成明细 + 扣库存」，且任一步失败时全部回滚；状态流转正确。

## 一、本阶段要学的新技能

| 技能 | 说明 |
| --- | --- |
| **事务 `@Transactional`** | 保证多个数据库操作「要么全成功，要么全失败」 |
| 订单号生成 | 生成唯一、可读的订单号 |
| 订单状态机 | 明确状态及其合法流转 |
| 快照思想 | 明细保存商品名与成交价快照 |
| 库存原子扣减 | 避免「先查后改」的超卖问题 |

## 二、订单状态机（先想清楚再写）

订单从创建到结束，状态按规则流转：

```
          ┌─────────────── 取消 ───────────────┐
          │                                     ▼
待支付(0) ── 支付成功 ──► 已支付(1)            已取消(2)
          │
          └─────────────── 超时/主动取消 ──────► 已取消(2)
```

| 订单状态 | 值 | 含义 |
| --- | --- | --- |
| 待支付 | 0 | 刚下单，未付款 |
| 已支付 | 1 | 支付完成 |
| 已取消 | 2 | 订单取消（库存需回补） |

> 学习期用 3 个状态即可，真实电商还有「已发货/已完成/退款」等，阶段八可扩展。

## 四、下单流程（核心）

下单要同时做三件事，且必须「原子化」：

```
1. 校验商品存在、有库存
2. 生成订单 + 订单明细（快照）
3. 扣减库存
```

任何一步失败，前面做的都要回滚。这就是**事务**。

### 1. DTO

```java
@Data
public class OrderCreateDTO {

    @NotNull(message = "店家ID不能为空")
    private Long merchantId;

    @NotBlank(message = "买家姓名不能为空")
    private String buyerName;

    private String buyerPhone;

    @NotEmpty(message = "订单明细不能为空")
    private List<OrderItemDTO> items;

    @Data
    public static class OrderItemDTO {
        @NotNull(message = "商品ID不能为空")
        private Long productId;

        @NotNull(message = "数量不能为空")
        @Min(value = 1, message = "数量至少为1")
        private Integer quantity;
    }
}
```

### 2. Service（含事务）

```java
@Service
public class OrderService extends ServiceImpl<OrderMapper, Order> {

    private final ProductService productService;
    private final OrderItemMapper orderItemMapper;

    public OrderService(ProductService productService, OrderItemMapper orderItemMapper) {
        this.productService = productService;
        this.orderItemMapper = orderItemMapper;
    }

    @Transactional(rollbackFor = Exception.class)   // 关键：声明事务
    public OrderVO createOrder(OrderCreateDTO dto) {

        // 1. 计算总额，同时校验商品与库存
        BigDecimal totalAmount = BigDecimal.ZERO;
        List<OrderItem> items = new ArrayList<>();

        for (OrderCreateDTO.OrderItemDTO itemDTO : dto.getItems()) {
            Product product = productService.getById(itemDTO.getProductId());
            if (product == null) {
                throw new BusinessException("商品不存在: " + itemDTO.getProductId());
            }
            if (product.getStock() < itemDTO.getQuantity()) {
                throw new BusinessException("商品库存不足: " + product.getName());
            }
            // 2. 构造明细快照
            OrderItem item = new OrderItem();
            item.setProductId(product.getId());
            item.setProductName(product.getName());
            item.setPrice(product.getPrice());
            item.setQuantity(itemDTO.getQuantity());
            item.setAmount(product.getPrice().multiply(BigDecimal.valueOf(itemDTO.getQuantity())));
            items.add(item);

            totalAmount = totalAmount.add(item.getAmount());

            // 3. 原子扣减库存
            int rows = productMapper.deductStock(product.getId(), itemDTO.getQuantity());
            if (rows == 0) {
                throw new BusinessException("库存不足: " + product.getName());
            }
        }

        // 4. 保存订单
        Order order = new Order();
        order.setOrderNo(generateOrderNo());
        order.setMerchantId(dto.getMerchantId());
        order.setBuyerName(dto.getBuyerName());
        order.setBuyerPhone(dto.getBuyerPhone());
        order.setTotalAmount(totalAmount);
        order.setStatus(0);      // 待支付
        order.setPayStatus(0);   // 未支付
        this.save(order);

        // 5. 保存明细（关联订单ID）
        for (OrderItem item : items) {
            item.setOrderId(order.getId());
            orderItemMapper.insert(item);
        }

        return toVO(order);
    }

    // 取消订单：回补库存
    @Transactional(rollbackFor = Exception.class)
    public void cancelOrder(Long id) {
        Order order = this.getById(id);
        if (order == null) {
            throw new BusinessException("订单不存在");
        }
        if (order.getStatus() != 0) {
            throw new BusinessException("只有待支付订单才能取消");
        }
        // 回补库存
        List<OrderItem> items = orderItemMapper.selectList(
                new QueryWrapper<OrderItem>().eq("order_id", id));
        for (OrderItem item : items) {
            productMapper.addStock(item.getProductId(), item.getQuantity());
        }
        order.setStatus(2);   // 已取消
        this.updateById(order);
    }

    private String generateOrderNo() {
        // 时间戳 + 随机数，学习期够用；生产可用雪花算法
        return "ORD" + System.currentTimeMillis() + (int)(Math.random() * 1000);
    }
}
```

## 五、事务的关键点

1. **`@Transactional(rollbackFor = Exception.class)`**：默认只对 `RuntimeException` 回滚，显式指定 `rollbackFor = Exception.class` 更保险。
2. **事务边界在 Service 方法上**：整个 `createOrder` 作为一个事务，方法正常结束才提交，抛异常则全部回滚。
3. **数据库引擎必须是 InnoDB**（建表时已指定），MyISAM 不支持事务。

> 前端视角：事务就像「原子操作」，类似一次必须整体成功的批量提交——要么全部生效，要么全部撤销，不存在中间态。

## 六、库存原子扣减（防超卖）

阶段五用的是「先查库存，再更新」，高并发下会超卖。正确做法是**原子扣减**——让数据库在更新时同时判断库存：

```java
@Mapper
public interface ProductMapper extends BaseMapper<Product> {

    // 原子扣减：只有库存充足时才会更新成功
    @Update("UPDATE product SET stock = stock - #{quantity} " +
            "WHERE id = #{productId} AND stock >= #{quantity}")
    int deductStock(@Param("productId") Long productId, @Param("quantity") Integer quantity);

    @Update("UPDATE product SET stock = stock + #{quantity} WHERE id = #{productId}")
    int addStock(@Param("productId") Long productId, @Param("quantity") Integer quantity);
}
```

`deductStock` 返回受影响行数：返回 1 表示扣减成功，返回 0 表示库存不足。因为 `WHERE stock >= quantity` 保证了并发下也不会扣成负数。

## 七、订单查询

```java
public Page<OrderVO> page(Long merchantId, Integer status, int pageNum, int pageSize) {
    QueryWrapper<Order> wrapper = new QueryWrapper<>();
    if (merchantId != null) {
        wrapper.eq("merchant_id", merchantId);
    }
    if (status != null) {
        wrapper.eq("status", status);
    }
    wrapper.orderByDesc("id");
    Page<Order> page = this.page(new Page<>(pageNum, pageSize), wrapper);

    Page<OrderVO> voPage = new Page<>(pageNum, pageSize, page.getTotal());
    voPage.setRecords(page.getRecords().stream().map(this::toVO).toList());
    return voPage;
}
```

订单详情还应带出明细列表：

```java
public OrderVO getOrderDetail(Long id) {
    Order order = this.getById(id);
    if (order == null) {
        throw new BusinessException("订单不存在");
    }
    OrderVO vo = toVO(order);
    List<OrderItem> items = orderItemMapper.selectList(
            new QueryWrapper<OrderItem>().eq("order_id", id));
    vo.setItems(items);   // 明细列表
    return vo;
}
```

## 八、验收清单

- [ ] 下单成功：生成订单 + 明细 + 库存正确扣减
- [ ] 库存不足时下单失败，且**订单、明细都未写入**（事务回滚）
- [ ] 明细里保存的是商品名/价格的快照
- [ ] 订单号唯一且格式正确
- [ ] 取消订单后库存回补、状态变为「已取消」
- [ ] 只有待支付订单可取消，其他状态取消被拦截
- [ ] 分页查询按店家、状态过滤正常

## 九、常见坑

| 问题 | 原因与解决 |
| --- | --- |
| 事务没生效 | 方法必须通过 Spring 代理调用（同类内 this 调用不会走事务）；类要 `@Service` |
| 库存扣成负数 | 用原子扣减 `WHERE stock >= quantity`，别用「先查后改」 |
| 金额计算不精确 | 用 `BigDecimal`，`multiply`/`add` 方法计算，勿用 double |
| `order` 表名报错 | 用 `` `order` `` 或改名 `orders`，实体用 `@TableName` 对应 |
| 取消订单不回补库存 | 忘记在取消事务里 `addStock` |
