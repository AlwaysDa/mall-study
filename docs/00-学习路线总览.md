# 00 · 学习路线总览

> 本章回答三个问题：**学什么、按什么顺序学、每个阶段做到什么程度算过关**。

## 一、学习理念

本路线遵循三条原则：

1. **由浅入深，逐层递进**：先跑通一个 Hello World，再学会操作数据库，最后组装成完整业务模块。每一步都建立在上一步之上。
2. **以「可运行」为验收标准**：每个阶段都有明确的「验收清单」，代码跑得起来、接口调得通，才算完成该阶段。
3. **先跑通，再优化**：先写出「能用」的代码，再在进阶阶段学习「好用」的工程化手段（鉴权、缓存、测试、部署）。

## 三、里程碑

建议给自己设定四个里程碑，每个里程碑完成后停下来复盘一次：

- **里程碑 A（阶段 0~2 完成后）**：掌握了「请求进来 → 处理 → 数据落库 → 响应返回」的完整链路。你已经能独立写一个带数据库的小接口了。
- **里程碑 B（阶段 3~5 完成后）**：掌握了「规范化分层 + 完整业务模块」的开发套路。店家管理 + 货物管理两个模块已经上线。
- **里程碑 C（阶段 6~8 完成后）**：完成了订单与支付这一最复杂的交易链路，并补齐了鉴权、缓存、文档、测试等工程化能力，得到了一个可部署的店家后台。
- **里程碑 D（阶段 9 完成后）**：补齐买家账户、购物车与履约流程，买家与店家两种角色在同一套系统里完成「浏览 → 下单 → 支付 → 发货 → 收货」，交易闭环正式跑通。

## 四、学习节奏建议

### 建议顺序（不要跳步）

```
环境搭建 → 阶段一 → 阶段二 → 阶段三 → 阶段四 → 阶段五 → 阶段六 → 阶段七 → 阶段八 → 阶段九
```

每一阶段都严格依赖前一阶段的成果。尤其：

- **阶段三（架构）是分水岭**：阶段三之前是在「学语法、学框架」，阶段三之后是在「做业务」。务必把统一返回体、全局异常、分层结构吃透，后面的三个业务模块都是在这个骨架上堆功能。
- **阶段六（订单）是最难的一关**：涉及事务、库存扣减、状态机，是真实电商业务的核心。这里多花时间值得。

### 给前端开发者的心理预期

| 前端熟悉的概念 | 后端对应概念 | 说明 |
| --- | --- | --- |
| 组件分层（UI/逻辑/数据） | Controller / Service / Mapper 分层 | 同样是「职责分离」，只是换了个名字 |
| `axios` 封装 / API 层 | Service 层 / 统一返回体 | 都是把「取数据」这件事收口 |
| TypeScript `interface` | DTO / Entity / VO | 都是「数据结构定义」 |
| 路由守卫 / 中间件 | 拦截器 / 过滤器 | 都是「请求进来先做点事」 |
| `localStorage` 存 token | JWT 无状态鉴权 | 都是「记住我是谁」 |
| 组件生命周期 | Bean 生命周期 / 事务边界 | 都需要理解「何时创建、何时销毁」 |

**最大的思维差异**：前端是「状态驱动视图」，后端是「数据经过校验、转换、持久化后返回」。理解并适应这个差异，转型就成功了一大半。

## 五、贯穿全程的良好习惯

1. **先建表，后写代码**：数据库表结构是业务的地基，动手写接口前先把表设计好。
2. **接口先定契约，再写实现**：先想清楚「入参是什么、返回什么、错误码是什么」，再写 Controller。
3. **每完成一个接口，用工具测一遍**：推荐 Postman 或 Apifox，不要只靠「编译通过」来判断完成。
4. **遇到报错，读堆栈**：Java 的报错堆栈信息量极大，最底下那几行往往就是根因。
