# 04 · 阶段三：商城项目架构

> 目标：搭建一个「规范、可复用」的商城项目骨架，为后续三大业务模块打好地基。  
> 验收标准：项目有清晰的分层包结构、统一的接口返回格式、全局异常处理，以及完整的建表 SQL。

## 一、本阶段的意义

阶段一、二你学会了「怎么写一个接口」。但从现在起，你要开始「怎么写一个**项目**」。

一个项目有成百上千个接口，如果每个接口的返回格式都不一样、错误处理各写各的，会变成灾难。所以本阶段先统一三件事：

1. **统一的分层结构**（包怎么分）
2. **统一的返回格式**（接口统一返回 `Result<T>`）
3. **统一的异常处理**（报错统一走全局异常处理器）

这三个「统一」会让后续所有业务模块的代码又规整又好写。

## 二、分层架构与包结构

```
com.mall.mall
├── MallApplication.java        # 启动类
├── controller                  # 控制层：接请求、回响应
├── service                     # 业务层：业务逻辑
│   └── impl                    #    业务层实现（可选，简单项目可省）
├── mapper                      # 数据访问层：MyBatis-Plus Mapper
├── entity                      # 实体类：对应数据库表
├── dto                         # 数据传输对象：接口入参
├── vo                          # 视图对象：接口出参（返回给前端的数据）
├── common                      # 通用：统一返回、异常、常量
│   ├── Result.java             #   统一返回体
│   ├── ErrorCode.java          #   错误码枚举
│   └── BusinessException.java  #   业务异常
├── config                      # 配置类
└── handler                     # 全局异常处理器
```

### 为什么要 DTO / VO，而不是直接用 Entity？

| 对象     | 用途       | 说明                  |
| ------ | -------- | ------------------- |
| Entity | 对应数据库表   | 和表字段一一对应            |
| DTO    | 接口**入参** | 只接收前端需要传的字段，可加校验注解  |
| VO     | 接口**出参** | 只返回前端需要看的字段，可隐藏敏感字段 |

> 前端视角：DTO/VO 就像 TypeScript 里为「请求」和「响应」分别定义的 interface，避免把数据库结构直接暴露给前端。**绝不让 Entity 直接作为接口入参/出参**，这是后端的重要规范（比如密码字段就不能随 VO 返回）。

## 三、统一返回体 Result

```java
package com.mall.mall.common;

import lombok.Data;

@Data
public class Result<T> {

    private Integer code;      // 状态码：0 成功，非 0 失败
    private String message;    // 提示信息
    private T data;            // 数据

    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.code = 0;
        r.message = "success";
        r.data = data;
        return r;
    }

    public static <T> Result<T> success() {
        return success(null);
    }

    public static <T> Result<T> fail(Integer code, String message) {
        Result<T> r = new Result<>();
        r.code = code;
        r.message = message;
        return r;
    }
}
```

之后所有接口统一返回 `Result<T>`，前端看到的格式永远是：

```json
{ "code": 0, "message": "success", "data": { ... } }
```

## 四、错误码与业务异常

### 1. 错误码枚举

```java
package com.mall.mall.common;

import lombok.Getter;

@Getter
public enum ErrorCode {

    SUCCESS(0, "成功"),
    PARAM_ERROR(400, "参数错误"),
    NOT_FOUND(404, "资源不存在"),
    UNAUTHORIZED(401, "未登录或登录已过期"),
    FORBIDDEN(403, "无权限"),
    BUSINESS_ERROR(500, "业务处理失败");

    private final Integer code;
    private final String message;

    ErrorCode(Integer code, String message) {
        this.code = code;
        this.message = message;
    }
}
```

### 2. 业务异常

```java
package com.mall.mall.common;

import lombok.Getter;

@Getter
public class BusinessException extends RuntimeException {

    private final Integer code;

    public BusinessException(ErrorCode errorCode) {
        super(errorCode.getMessage());
        this.code = errorCode.getCode();
    }

    public BusinessException(String message) {
        super(message);
        this.code = ErrorCode.BUSINESS_ERROR.getCode();
    }
}
```


## 五、全局异常处理器

```java
package com.mall.mall.handler;

import com.mall.mall.common.BusinessException;
import com.mall.mall.common.Result;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

@RestControllerAdvice
public class GlobalExceptionHandler {

    // 业务异常
    @ExceptionHandler(BusinessException.class)
    public Result<Void> handleBusinessException(BusinessException e) {
        return Result.fail(e.getCode(), e.getMessage());
    }

    // 其他未知异常
    @ExceptionHandler(Exception.class)
    public Result<Void> handleException(Exception e) {
        // 生产环境应记录日志，这里先打印
        e.printStackTrace();
        return Result.fail(500, "系统内部错误");
    }
}
```

有了它，Service 里出错时直接 `throw new BusinessException("商品不存在")`，就会自动转成统一格式返回，Controller 里不再需要到处 try-catch。

```java
public Product getProduct(Long id) {
    Product p = productService.getById(id);
    if (p == null) {
        throw new BusinessException("商品不存在");
    }
    return p;
}
```

## 六、商城数据库设计（核心！）

> 这是整个项目的地基，动手前先吃透。所有表统一 `utf8mb4` + `InnoDB`，主键统一 `BIGINT AUTO_INCREMENT`。

### 表关系图

```
merchant（店家） 1 ──┬── n product（商品） n ── 1 category（分类）
                    │
                    └── n order（订单） 1 ── n order_item（订单明细）
```

### 1. 店家表 merchant

```sql
CREATE TABLE merchant (
    id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '店家ID',
    username    VARCHAR(50)  NOT NULL                COMMENT '登录账号',
    password    VARCHAR(100) NOT NULL                COMMENT '密码（BCrypt加密）',
    shop_name   VARCHAR(100) NOT NULL                COMMENT '店铺名称',
    contact     VARCHAR(50)                          COMMENT '联系人',
    phone       VARCHAR(20)                          COMMENT '联系电话',
    status      TINYINT      NOT NULL DEFAULT 1      COMMENT '状态：1正常 0禁用',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_username (username)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='店家表';
```

### 2. 商品分类表 category

```sql
CREATE TABLE category (
    id          BIGINT       NOT NULL AUTO_INCREMENT COMMENT '分类ID',
    name        VARCHAR(50)  NOT NULL                COMMENT '分类名',
    sort        INT          NOT NULL DEFAULT 0      COMMENT '排序值，越小越靠前',
    create_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品分类表';
```

### 3. 商品表 product

```sql
CREATE TABLE product (
    id           BIGINT        NOT NULL AUTO_INCREMENT COMMENT '商品ID',
    merchant_id  BIGINT        NOT NULL                COMMENT '所属店家ID',
    category_id  BIGINT        NOT NULL                COMMENT '分类ID',
    name         VARCHAR(100)  NOT NULL                COMMENT '商品名',
    description  VARCHAR(500)                          COMMENT '商品描述',
    price        DECIMAL(10,2) NOT NULL                COMMENT '价格',
    stock        INT           NOT NULL DEFAULT 0      COMMENT '库存',
    status       TINYINT       NOT NULL DEFAULT 1      COMMENT '状态：1上架 0下架',
    main_image   VARCHAR(255)                          COMMENT '主图URL',
    create_time  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time  DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    KEY idx_merchant (merchant_id),
    KEY idx_category (category_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='商品表';
```

### 4. 订单表 `order`（注意：order 是 SQL 关键字，表名要加反引号或用 `orders`）

```sql
CREATE TABLE `order` (
    id            BIGINT        NOT NULL AUTO_INCREMENT COMMENT '订单ID',
    order_no      VARCHAR(32)   NOT NULL                COMMENT '订单号',
    merchant_id   BIGINT        NOT NULL                COMMENT '店家ID',
    buyer_name    VARCHAR(50)                           COMMENT '买家姓名',
    buyer_phone   VARCHAR(20)                           COMMENT '买家电话',
    total_amount  DECIMAL(10,2) NOT NULL                COMMENT '订单总额',
    status        TINYINT       NOT NULL DEFAULT 0      COMMENT '订单状态：0待支付 1已支付 2已取消',
    pay_status    TINYINT       NOT NULL DEFAULT 0      COMMENT '支付状态：0未支付 1已支付',
    create_time   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP,
    update_time   DATETIME      NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uk_order_no (order_no),
    KEY idx_merchant (merchant_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单表';
```

### 5. 订单明细表 order_item

```sql
CREATE TABLE order_item (
    id           BIGINT        NOT NULL AUTO_INCREMENT COMMENT '明细ID',
    order_id     BIGINT        NOT NULL                COMMENT '订单ID',
    product_id   BIGINT        NOT NULL                COMMENT '商品ID',
    product_name VARCHAR(100)  NOT NULL                COMMENT '商品名（快照）',
    price        DECIMAL(10,2) NOT NULL                COMMENT '成交单价（快照）',
    quantity     INT           NOT NULL                COMMENT '数量',
    amount       DECIMAL(10,2) NOT NULL                COMMENT '小计 = price * quantity',
    PRIMARY KEY (id),
    KEY idx_order (order_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='订单明细表';
```

**设计要点：**

| 要点                 | 说明                                            |
| ------------------ | --------------------------------------------- |
| 订单明细「快照」           | 明细里存 `product_name`/`price` 的副本，商品后来改价不影响历史订单 |
| 金额用 `DECIMAL`      | 全程用 `BigDecimal`，杜绝精度丢失                       |
| 唯一索引 `uk_order_no` | 保证订单号唯一，防重复下单                                 |
| 普通索引               | 高频查询字段（`merchant_id`、`order_id`）建索引，加快查询      |

> 后续章节会把这些建表 SQL 合并到一个 `sql/schema.sql` 文件里统一管理，方便一键初始化。


## 七、参数校验（引入 Validation）

> 依赖库速览：`spring-boot-starter-validation` 是 Spring 官方的**参数校验启动器**（底层是 Jakarta Validation + Hibernate Validator）。它把「字段合法性检查」变成注解声明——不用在每个接口里手写一堆 `if (xxx == null)`，DTO 字段上标一个 `@NotBlank` 就够了，校验失败会抛异常，正好被阶段三的全局异常处理器接住返回统一格式。

依赖：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>
```

在 DTO 上加校验注解，Controller 用 `@Valid` 触发：

```java
@Data
public class MerchantRegisterDTO {
    @NotBlank(message = "账号不能为空")
    private String username;

    @Size(min = 6, max = 20, message = "密码长度需在6-20位之间")
    private String password;

    @NotBlank(message = "店铺名称不能为空")
    private String shopName;
}
```

```java
@PostMapping("/register")
public Result<Void> register(@Valid @RequestBody MerchantRegisterDTO dto) {
    merchantService.register(dto);
    return Result.success();
}
```

> 说明：上面的 `MerchantRegisterDTO` 是**阶段四（店家注册）**&#x624D;会正式用到的 DTO，这里只是借用它演示 `@Valid` 的触发方式，**阶段三不需要建它**。本阶段你只需体会「校验注解 + @Valid」这套机制即可：可以在 `com.mall.mall.dto` 包（若还没有 dto 包就新建一个）参照它建一个自己的 DTO 练手，例如给商品模块建 `ProductCreateDTO`——`name` 标 `@NotBlank`、`price` 标 `@NotNull`，再写一个临时测试接口触发校验，跑通验收清单里「带 @Valid 校验的接口」一条。各模块正式的业务 DTO 会从阶段四开始按需逐个创建。

常用校验注解：`@NotBlank`、`@NotNull`、`@Size`、`@Email`、`@Pattern`、`@Min`/`@Max`。

## 九、常见坑

| 问题            | 原因与解决                                          |
| ------------- | ---------------------------------------------- |
| `order` 表建不出来 | `order` 是关键字，用反引号 `` `order` `` 或改名 `orders`   |
| 全局异常没生效       | 检查 `@RestControllerAdvice` 类是否被扫描到（在启动类同包或子包下） |
| 校验注解没生效       | Controller 参数漏了 `@Valid`                       |
| 返回数据多出密码字段    | 出参用 VO 而非 Entity，别把 Entity 直接返回                |
